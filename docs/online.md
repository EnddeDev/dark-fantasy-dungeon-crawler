# СУМРАК онлайн: аккаунты, база данных и общие вкладки

Игра умеет работать в двух режимах:

- **соло** — как раньше, прогресс в `localStorage` браузера, если сервер недоступен;
- **онлайн** — вход по логину и паролю, прогресс в базе на сервере, вкладки «Игроки», «Рынок»,
  «Обмены», «Дуэли» и «Чат».

Режим выбирается автоматически: клиент спрашивает `GET /api/health`, и если сервер молчит,
игра стартует в соло-режиме и показывает кнопку «Войти».

## Запуск

```bash
npm ci
npm run server      # API + SQLite на http://0.0.0.0:8787
npm run dev         # интерфейс на http://0.0.0.0:5173, /api проксируется на 8787
```

Переменные окружения сервера:

| Переменная | Значение по умолчанию | Зачем |
| --- | --- | --- |
| `PORT` | `8787` | порт API |
| `DB_FILE` | `server/data/sumrak.db` | файл SQLite |
| `API_PROXY` | `http://127.0.0.1:8787` | адрес API для прокси Vite |
| `VITE_API_URL` | `/api` | адрес API, который использует браузер |

Файлы базы и сборки сервера (`server/data/`, `server/.build/`) в Git не попадают.

## Схема базы

```
users(id, login, pass, created_at)          — аккаунт, пароль хранится как scrypt-хеш с солью
sessions(token, user_id, created_at, seen_at) — сессии, «онлайн» = активность за последнюю минуту
profiles(user_id, name, level, best_floor, gold, save, updated_at)
                                            — герой целиком в save (JSON) + быстрые поля для витрин
friends(user_id, friend_id, created_at)     — дружба двусторонняя, две строки
trades(id, from_id, to_id, status, offer, request, message, …)
                                            — обмен: offer — вещи автора, request — встречный набор
market(id, seller_id, item, price, status, buyer_id, …)
                                            — лоты; предмет лежит в эскроу, пока лот активен
duels(id, challenger, opponent, status, state, winner, …)
                                            — состояние боя в state (JSON)
messages(id, channel, from_id, body, created_at)
                                            — channel: global или dm:<id>:<id>
```

Правила сохранности:

- снаряжение из арсенала уходит в эскроу на время лота или обмена и возвращается при отмене;
- надетые вещи в сделки не попадают — сначала их нужно снять;
- золото покупателя и продавца меняется в одной транзакции с передачей предмета;
- пароли не хранятся в открытом виде, сессии — случайные токены в заголовке `Authorization: Bearer`.

## API

Все ответы — JSON, ошибки приходят как `{ "error": "текст" }` со статусом 4xx/5xx.

| Метод и путь | Что делает |
| --- | --- |
| `POST /api/auth/register` | регистрация `{login, password}` → `{token, profile}` |
| `POST /api/auth/login` | вход, тот же ответ |
| `POST /api/auth/logout` | закрывает сессию |
| `GET /api/me` / `PUT /api/me` | профиль с сохранением / запись прогресса |
| `GET /api/players?q=` | список игроков с максимальным этажом и онлайном |
| `GET/POST/DELETE /api/friends` | друзья, двусторонняя дружба |
| `GET /api/market`, `POST /api/market`, `POST /api/market/:id`, `DELETE /api/market/:id` | витрина, выставление, покупка, снятие лота |
| `GET/POST /api/trades`, `POST /api/trades/:id/{counter,accept,decline,cancel}` | обмен снаряжением |
| `GET/POST /api/duels`, `GET /api/duels/:id`, `POST /api/duels/:id/{accept,decline,cancel,action}` | дуэли |
| `GET/POST /api/chat/global` | общий чат |
| `GET/POST /api/chat/dm/:userId` | личные сообщения, только друзьям |

## Обмен

1. Автор выбирает свои вещи и отправляет предложение — они сразу уходят в эскроу.
2. Получатель видит набор и либо отказывается, либо присылает встречное предложение из своего арсенала.
3. Автор видит встречный набор и принимает (вещи меняются местами в одной транзакции) или отказывается.
4. Отмена и отказ всегда возвращают вещи владельцам.

Статусы: `offered → countered → accepted | declined`, плюс `cancelled`.

## Дуэли

- Вызов → соперник принимает или отклоняет; одновременно у игрока может быть только один вызов или бой.
- На каждый ход даётся **20 секунд**: сервер хранит `deadline`, и по истечении ход переходит сопернику
  (действия сгорают). Время проверяется на каждом запросе клиента.
- Бой идёт по формулам подземелья: здоровье от Силы, урон оружия и `strFlat`, уклонение и крит от Ловкости,
  броня срезает урон, защита уменьшает его вдвое, приём оружия требует Интеллекта и перезаряжается.
- Действия: удар, приём, защита, зелье, пропуск. За ход можно сделать столько действий, сколько даёт
  Ловкость (1–4).

## Чаты

- Общий чат видят все авторизованные игроки.
- Личные сообщения доступны только друзьям; канал строится из двух id, поэтому история общая для пары.
- Сообщения длиной до 400 символов, опрос раз в 3 секунды, история — последние 200 сообщений.

## Внешний BaaS (Supabase/Firebase)

Клиент общается с сервером только через `src/net/api.ts`, поэтому площадку можно заменить,
не трогая интерфейс: адрес задаётся `VITE_API_URL`.

Что уже готово:

- контракт API и все типы — `src/net/protocol.ts`;
- SQL-схема для Postgres/Supabase — `supabase/schema.sql`;
- список функций, которые нужно перенести на сторону базы (атомарность покупок, обменов и дуэлей), — `supabase/README.md`.

Что нужно, чтобы включить настоящий BaaS: URL проекта и публичный anon-ключ. После этого клиент
переключается на `https://<project>.supabase.co/functions/v1/api` (или PostgREST), а сервер из `server/`
можно выключить.
