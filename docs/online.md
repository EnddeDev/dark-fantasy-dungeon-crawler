# СУМРАК онлайн: аккаунты, база данных и общие вкладки

Игра умеет работать в двух режимах:

- **соло** — как раньше, прогресс в `localStorage` браузера, если сервер недоступен;
- **онлайн** — вход по логину и паролю, прогресс в базе на сервере, вкладки «Игроки», «Рынок»,
  «Обмены», «Дуэли» и «Чат». Изменения приходят сами (поток SSE), уведомления — в игре и браузерные.

Режим выбирается автоматически: клиент спрашивает `GET /api/health`, и если сервер молчит,
игра стартует в соло-режиме и показывает кнопку «Войти».

## Запуск

```bash
npm ci
npm run server      # API + SQLite на http://0.0.0.0:8787
npm run dev         # интерфейс на http://0.0.0.0:5173, /api проксируется на 8787
```

Переменные окружения сервера:

| Переменная | Значение по умолчанию | Зачем |
| --- | --- | --- |
| `PORT` | `8787` | порт сервера (API и игра) |
| `DIST_DIR` | `dist` | папка с собранной игрой; если нет — сервер работает только как API |
| `DB_FILE` | `server/data/sumrak.db` | файл SQLite |
| `API_PROXY` | `http://127.0.0.1:8787` | адрес API для прокси Vite |
| `VITE_API_URL` | `/api` | адрес API, который использует браузер |

Файлы базы и сборки сервера (`server/data/`, `server/.build/`) в Git не попадают.

## Один адрес для игры и API

Сервер умеет отдавать собранный клиент: если рядом лежит `dist/`, то `GET /` возвращает игру,
`/api/...` — API, а неизвестные пути — `index.html` (одностраничное приложение).
Сборка кэшируется правильно: у хешированных файлов долгий `immutable`, у `index.html` — `no-store`,
поэтому обновления игры доезжают сразу.

```bash
npm ci
npm run build      # клиент в dist/
npm run start      # сервер + игра на http://0.0.0.0:8787
```

Развернуть публично можно так:

- **Docker** — `docker build -t sumrak . && docker run -p 8787:8787 -v sumrak:/data sumrak`;
- **Render** — подключить репозиторий, платформа возьмёт `render.yaml`
  (Docker, диск `/data` для SQLite, health-check `/api/health`);
- любой VPS: `npm ci && npm run build && npm run start` под systemd/PM2.

После деплоя `VITE_API_URL` не нужен: клиент по умолчанию ходит в относительный `/api`.

## Если вместо ответа приходит HTML

Симптом: при регистрации всплывает `Unexpected token '<', "<html> <he"... is not valid JSON`.

Причина: запрос `/api/...` обслужил статический хостинг (GitHub Pages, любой nginx без прокси),
и вместо JSON вернул HTML-страницу. С версии после PR #19 клиент распознаёт такой ответ и показывает
понятное «Сервер недоступен: ответ не JSON», а экран входа объясняет, чего не хватает.

Что делать:

1. Открыть игру не через Pages, а через dev-сервер: `npm run server` и `npm run dev` (Vite проксирует `/api`).
2. Для публичной сборки развернуть сервер из `server/` и собрать с `VITE_API_URL=https://ваш-сервер/api`.
3. Если сервер развёрнут, но путь другой — проверить `VITE_API_URL` и CORS: сервер отвечает
   `Access-Control-Allow-Origin: *`, поэтому достаточно правильного адреса.

## Схема базы

```
users(id, login, pass, created_at)          — аккаунт, пароль хранится как scrypt-хеш с солью
sessions(token, user_id, created_at, seen_at) — сессии, «онлайн» = активность за последнюю минуту
profiles(user_id, name, level, best_floor, gold, save, updated_at)
                                            — герой целиком в save (JSON) + быстрые поля для витрин
friends(user_id, friend_id, created_at)     — дружба двусторонняя, две строки
portraits(user_id, data, updated_at)        — портрет: WEBP 256×256, BLOB; версия = updated_at
trades(id, from_id, to_id, status, offer, request, message, …)
                                            — обмен: offer — вещи автора, request — встречный набор
market(id, seller_id, item, price, status, buyer_id, …)
                                            — лоты; предмет лежит в эскроу, пока лот активен
duels(id, challenger, opponent, status, state, winner, …)
                                            — состояние боя в state (JSON)
messages(id, channel, from_id, body, created_at)
                                            — channel: global или dm:<id>:<id>
friend_requests(id, from_id, to_id, status, created_at, updated_at)
                                            — заявка pending → accepted | declined | cancelled
notifications(id, user_id, kind, ref_id, body, created_at, read_at)
                                            — уведомления; kind: dm, friend_request, friend_accepted,
                                              trade, duel, market_sale
```

Правила сохранности:

- снаряжение из арсенала уходит в эскроу на время лота или обмена и возвращается при отмене;
- надетые вещи в сделки не попадают — сначала их нужно снять;
- золото покупателя и продавца меняется в одной транзакции с передачей предмета;
- пароли не хранятся в открытом виде, сессии — случайные токены в заголовке `Authorization: Bearer`;
- `PUT /api/me` принимает героя целиком, но перед записью сервер проверяет его (`server/save.ts`): известные базы снаряжения, допустимые редкость/состояние/уровень, ссылки `equip` только на предметы из арсенала, характеристики в рамках очков уровня, потолки золота и сумки. Неизвестные поля отбрасываются, грубые нарушения дают 400. Полная защита от накрутки потребует серверного подсчёта экономики — сейчас урон ограничен потолками.

## API

Все ответы — JSON, ошибки приходят как `{ "error": "текст" }` со статусом 4xx/5xx.

| Метод и путь | Что делает |
| --- | --- |
| `POST /api/auth/register` | регистрация `{login, password}` → `{token, profile}` |
| `POST /api/auth/login` | вход, тот же ответ |
| `POST /api/auth/logout` | закрывает сессию |
| `GET /api/me` / `PUT /api/me` | профиль с сохранением / запись прогресса |
| `GET /api/players?q=&offset=&limit=` | порция игроков (по 20), `{players, hasMore}` |
| `GET /api/players/:id/profile` | профиль для просмотра: характеристики и экипировка |
| `GET /api/friends`, `DELETE /api/friends/:id` | друзья и удаление из друзей |
| `POST /api/friends` | то же, что `POST /api/friends/requests` (заявка) |
| `GET /api/friends/requests` | входящие и исходящие заявки |
| `POST /api/friends/requests` | заявка `{id}`; встречная заявка сразу даёт дружбу |
| `POST /api/friends/requests/:id/{accept,decline}` | ответ получателя |
| `DELETE /api/friends/requests/:id` | отзыв заявки автором |
| `GET /api/market?offset=&limit=`, `POST /api/market`, `POST /api/market/:id`, `DELETE /api/market/:id` | витрина порциями по 20, выставление, покупка, снятие лота |
| `GET/POST /api/trades`, `POST /api/trades/:id/{counter,accept,decline,cancel}` | обмен снаряжением |
| `GET/POST /api/duels`, `GET /api/duels/:id`, `POST /api/duels/:id/{accept,decline,cancel,action}` | дуэли |
| `GET/POST /api/chat/global` | общий чат |
| `GET/POST /api/chat/dm/:userId` | личные сообщения, только друзьям |
| `GET /api/notifications?since=` | счётчики непрочитанного по типам и последние уведомления |
| `POST /api/notifications/read` | `{kinds?}` — пометить прочитанными типы раздела (или все) |
| `GET /api/events` | поток событий (Server-Sent Events), нужен вход |

## Профиль

Профиль показывает имя, уровень, СИЛ, ЛОВ и ИНТ, экипировку по слотам (Оберег, Шлем, Тело, Наручи,
Правая и Левая рука, Кольца I и II, Ботинки) и состояние дружбы. Золото, сундук, сумку, архетип,
рекорд этажа и историю боёв сервер не отдаёт: ответ собирается из отдельных полей, сырой JSON героя
наружу не уходит. Из профиля можно написать (только друзьям), предложить обмен или вызвать на дуэль.

## Портреты

Игрок может загрузить портрет на вкладке «Профиль» сообщества. Портрет виден всем: в списке игроков,
профиле, заявках, друзьях, чате, рынке, обменах и дуэлях (на карточках арены вместо инициала).

- `PUT /api/me/portrait` — сырой файл (`Content-Type`: `image/jpeg`, `image/png` или `image/webp`), до 2 МБ.
  Тип определяется по сигнатуре файла. Сервер через `sharp` поворачивает картинку по EXIF, обрезает
  по центру до 256×256 и сохраняет WEBP. Ответы: 415 — не картинка, 413 — больше 2 МБ, 401 — нет входа.
- `DELETE /api/me/portrait` — убрать портрет.
- `GET /api/players/:id/portrait` — сама картинка. Открытая (тег `<img>` не шлёт `Authorization`),
  кэш через `ETag`, адрес клиента добавляет версию `?v=` и сбрасывает кэш при замене.
- В ответах с игроками поле `portrait` — версия (число) или `null`. У обмена, чата, рынка и дуэли
  версии автора и участников: `fromPortrait`, `toPortrait`, `sellerPortrait`, `challengerPortrait`, `opponentPortrait`.
- Модерации нет: портрет виден сразу, владелец может заменить или удалить его.

**Важно для VPS:** nginx по умолчанию пропускает тело запроса до 1 МБ, а портрет может весить до 2 МБ.
В блоке `server` сайта добавить `client_max_body_size 3m;` и выполнить `sudo nginx -t && sudo systemctl reload nginx`.
Без этого загрузки больше 1 МБ получат ответ 413 от nginx, ещё до сервера.

## Друзья по заявкам

Заявка создаёт строку `friend_requests` со статусом `pending`. Дружба появляется только после
подтверждения получателем: тогда создаются две строки в `friends`. Если два игрока отправили заявки
друг другу, дружба возникает сразу. Исходящих заявок одновременно не больше 50.

## Живые обновления и уведомления

- **Поток `GET /api/events`.** Клиент открывает его через `fetch` с заголовком `Authorization`
  (EventSource такой заголовок не передаёт). Сервер шлёт короткие подсказки: `chat`, `market`,
  `trade`, `duel`, `friend`, `notification`, `players`. Данные раздел берёт обычным запросом.
  Сервер пингует поток каждые 25 секунд. На одного игрока открыто не больше 5 потоков.
- **Опрос как запасной путь.** Если поток недоступен, разделы опрашивают сервер как раньше
  (чат 3 с, обмены 4 с, рынок 8 с, список игроков 30 с). Пока поток работает, опрос редкий.
  Дуэль опрашивается всегда часто: таймер хода истекает на сервере без события.
- **Уведомления в игре.** Бейдж на вкладке и на кнопке «Сообщество», всплывающая подсказка на 6 секунд.
  Открытие раздела помечает его уведомления прочитанными.
- **Браузерные уведомления.** Через `Notification API`, только когда вкладка скрыта. Разрешение
  запрашивается кнопкой в шапке сообщества (браузеры требуют жеста пользователя).
- **Списки.** Рынок и игроки подгружаются порциями по 20 при прокрутке (`offset`, `limit`).

### Правка nginx на VPS

Поток `/api/events` не должен буферизоваться и не должен обрываться по таймауту. В блоке `server`
нужного сайта, перед общим `location /api/`, добавить:

```nginx
location = /api/events {
    proxy_pass http://127.0.0.1:8787;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header Connection "";
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 1h;
    chunked_transfer_encoding on;
}
```

После правки: `sudo nginx -t && sudo systemctl reload nginx`. Сервер сам отдаёт
`X-Accel-Buffering: no`, но явный `proxy_buffering off` на VPS надёжнее. Шаблон
`deploy-vps.sh` в репозиторий пока не добавлен: правка внесена на сервере вручную.

## Обмен

1. Автор выбирает свои вещи и отправляет предложение — они сразу уходят в эскроу.
2. Получатель видит набор и либо отказывается, либо присылает встречное предложение из своего арсенала.
3. Автор видит встречный набор и принимает (вещи меняются местами в одной транзакции) или отказывается.
4. Отмена и отказ всегда возвращают вещи владельцам.

Статусы: `offered → countered → accepted | declined`, плюс `cancelled`.

## Дуэли

- Вызов → соперник принимает или отклоняет; одновременно у игрока может быть только один вызов или бой.
- На каждый ход даётся **20 секунд**: сервер хранит `deadline`, и по истечении ход переходит сопернику
  (действия сгорают). Время проверяется на каждом запросе клиента.
- Правила боя подземелья: выносливость (старт — половина максимума, +20 в начале своего хода), концентрация
  (макс. 7, сброс в начале дуэли), удары по каждому оружию, виды удара (мощный / обычный / точный) с меткостью
  и уклонением, крит, броня, приём оружия (требует Интеллект и концентрацию 1, тратит выносливость и концентрацию).
- Действия: удар (мощный тратит концентрацию 1, точный даёт +1), приём, спец-приём архетипа (концентрация 5),
  зелье (тратит выносливость 5), защита (тратит 10, броня +10 до начала своего хода, ход не заканчивается),
  пропуск хода (заканчивает ход), сдача (засчитывается поражение, выносливость не тратится).
- За ход можно сделать столько действий, сколько даёт Ловкость (1–4). Защита действие не тратит.
- Спец-приёмы архетипов в дуэли: Варвар — удар на недостающее здоровье; Стойка-щит — защита, лечение на броню
  и щит к следующему удару; Ассасин — критический удар с вампиризмом 20%; Дуэлянт — ответный залп и раскол брони
  −3 на 2 раунда; Колдун — жертвенный пакт (здоровье 50%, неуязвимость до своего хода, иссушение врага);
  Архимаг — магический удар и горение или обморожение на 3 раунда (свитки в дуэли не создаются).
- Старые дуэли, сохранённые до этих правил, дополняются значениями по умолчанию при следующем запросе (`normalizeDuel`).

## Чаты

- Общий чат видят все авторизованные игроки.
- Личные сообщения доступны только друзьям; канал строится из двух id, поэтому история общая для пары.
- Сообщения длиной до 400 символов, история — последние 200 сообщений. Новые сообщения приходят
  событием `chat`, опрос раз в 3 секунды остаётся запасным путём.

## Внешний BaaS (Supabase/Firebase)

Клиент общается с сервером только через `src/net/api.ts`, поэтому площадку можно заменить,
не трогая интерфейс: адрес задаётся `VITE_API_URL`.

Что уже готово:

- контракт API и все типы — `src/net/protocol.ts`;
- SQL-схема для Postgres/Supabase — `supabase/schema.sql`;
- список функций, которые нужно перенести на сторону базы (атомарность покупок, обменов и дуэлей), — `supabase/README.md`.

Что нужно, чтобы включить настоящий BaaS: URL проекта и публичный anon-ключ. После этого клиент
переключается на `https://<project>.supabase.co/functions/v1/api` (или PostgREST), а сервер из `server/`
можно выключить.
